# Flock Map

Flock Safety / ALPR surveillance camera map — a static web app of licence-plate
reader cameras, refreshed weekly from OpenStreetMap (see "Data" below).

Served self-hosted at `https://chiefmonkey.art/flock-map/`. Version: see
[`VERSION`](VERSION) (currently **1.4.0**) — also live at `/flock-map/VERSION`
and on the homepage launcher tile.

## Files

Sources (edit these):

- `VERSION` — release version; drives the page, napplet, events and launcher tile
- `data/cams.source.js` — dataset `window.CAMS = [[lat, lon, name, operator, maker], ...]`,
  one record per line (written by `tools/refresh-osm.mjs`)
- `data/SOURCE.json` — provenance: source, licence, data date, map credit
- `web/index.src.html` — page template for both the web app and the napplet
- `vendor/leaflet.{js,css}` — vendored Leaflet 1.9.4 (inlined at build)
- `ops/` — VPS dispatcher, pinned root installer, one-time bootstrap
- `sign/index.html` — one-click signing helper (NIP-07): uploads the napplet to
  Blossom, then signs and publishes the napplet listing (35129), the ngit repo
  announcement (30617) and the repo state (30618). It reads `ngit/bundle.json`,
  which `tools/ngit-events.mjs` builds from the real git refs at signing time.
  Hosted only while signing: `.github/workflows/pages.yml` runs by hand and
  Pages is switched off afterwards.
- `tools/ngit-events.mjs` — prints the signing bundle; refuses unless main is
  tagged `v$VERSION`.

Generated by `node tools/build.mjs` (never edit by hand; CI fails if stale):

- `index.html` — web page: inlined Leaflet, single-canvas renderer, hash-pinned CSP
- `cams.js` — `window.FLOCK_PACK`, the dataset packed losslessly (Morton-sorted
  varint deltas at 1e-7°, dictionaries, deflate-raw, base64): 1.4 MB vs 7.6 MB
- `manifest.json` — per geohash-4 cell: camera count + sha256 of its records
- `napplet/index.html` — single-file napplet (same renderer, pack inlined)
- `napplet/dist/*.unsigned.json` — kind 35129 + kind 30617 events, unsigned

## Data

Cameras come straight from OpenStreetMap: every node tagged
`man_made=surveillance` + `surveillance:type=ALPR` (the same query DeFlock
uses). Data © OpenStreetMap contributors, ODbL 1.0; the credit and data date
are shown on the map.

Before v1.3.1 the map used a legacy Nov 2025 snapshot (Ringmast4r/FLOCK via a
Nostr republish signed by a key an earlier Computer session generated, not the
owner's).

**Weekly refresh** (`.github/workflows/refresh-data.yml`, Mondays 04:17 UTC,
or run it by hand): fetches from Overpass (with fallbacks), refuses obviously
broken replies (< 50,000 cameras or a > 25% drop), rebuilds, bumps the patch
version and opens or updates one pull request. Nothing changes on the VPS
until that PR is merged.

**Release on merge** (`.github/workflows/release.yml`): when main gets a
VERSION with no tag yet, it tests, tags that commit and starts the VPS deploy,
so VPS == tag == main. Docs-only merges do nothing.

**Moving to ngit:** the planned decentralised release path (ngit + GRASP,
VPS-side refresh, owner-signed approval) is drafted in
[`docs/adr/0001-ngit-decentralised-releases.md`](docs/adr/0001-ngit-decentralised-releases.md)
Phase 1 (v1.4.0) announces the repo on ngit under the owner's npub, hosted on
the GRASP servers relay.ngit.dev, gitnostr.com and git.shakespeare.diy plus
`wss://chiefmonkey.art/relay`, with GitHub as a mirror. Browse it on
[GitWorkshop](https://gitworkshop.dev/npub1a3um269aaf3u5cy37kuykrrrnsg2pyv7za06pxjduv25lq5sdujs2qmdj6/flock-map).
Until phase 3, releases still go through the GitHub path above, and the ngit
copy is refreshed whenever the owner signs a new state.

## Build and test

```sh
node tools/build.mjs && node tools/test.mjs && bash tools/test-ops.sh
```

CI runs both suites on every PR; the deploy workflow refuses to ship if they
fail or if it is not running from tag `v$(cat VERSION)`.

## Deploy security model

The deploy key is a **restricted key**: sshd forces it to run only
`/usr/local/bin/flock-map-deploy` — no shell, no pty, no port/agent/X11
forwarding. That dispatcher:

1. reads a gzipped tarball on stdin (16 MB cap),
2. validates it: **regular files only**, exactly `index.html`, `cams.js`,
   `manifest.json`, `VERSION` — no symlinks/hard links, paths, duplicates or
   >32 MB unpacked,
3. hands it to the pinned root installer via a single fixed-path sudoers rule
   (`ubuntu ALL=(root) NOPASSWD: /usr/local/sbin/flock-map-install-root`).

The root installer copies the payload into a root-only work dir, re-validates
it with the identical validator, extracts regular files only, checks `VERSION`
is strict `x.y.z`, flips `/apps/flock-map/current`, writes the nginx fragment
(gzip for JS/JSON/CSS, caching, and the site-wide security headers that a
location-level `add_header` would otherwise drop), runs `nginx -t` and **rolls
back fragment and release on failure**, registers the launcher tile at
`VERSION`, reloads nginx and keeps the newest 5 releases.

`ops/bootstrap-vps.sh` installs the dispatcher and installer byte-for-byte from
the `ops/` files at the deployed tag (passed in base64), so there is one copy
of each. It needs a one-time privileged path and is only re-run when `ops/`
changes.

## Deploy

```sh
gh workflow run deploy-flock-map.yml --repo ChiefmonkeyArt/flock-map --ref v$(cat VERSION)
```

The workflow verifies the VPS host-key fingerprint against the
`VPS_DEPLOY_HOST_KEY` secret before any remote command runs, then polls
`/flock-map/VERSION` until the new version is live.
